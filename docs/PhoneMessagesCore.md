# Phone Messages Core v1

Проект: `E:\GO! Live`, Unity `6000.6.0f1`.

Следующий этап Save/Load уже выполнен: см. [PhoneMessagesSaveIntegration.md](PhoneMessagesSaveIntegration.md). Ниже сохранён отчёт первоначального domain-only этапа; его пункты о ещё не подключённом Save описывают состояние на момент той сдачи. UI по-прежнему не подключён.

## Граница этапа

Добавлен самостоятельный pure C# domain layer. Нет новых MonoBehaviour, сервисов, глобального состояния, пакетов или изменений сцены. Существующий mock Messages UI остаётся прежним; он ещё не отображает данные этого ядра. Автоматические сообщения и отправка из UI не добавлены.

## Аудит и ответственность

| Существующий код | Ответственность / решение |
| --- | --- |
| `PhoneSession` | Навигация Home/Messages/Shop. Не изменён. |
| `PhoneBehaviour`, `PhonePointerBehaviour` | Появление, физическое управление телефоном и ввод. Не изменены. |
| `PhoneScreenView` | Mock-переписка, локализованные визуальные строки и preview unread. Оставлен без изменений. |
| `LocalizationContext`, `LocalizationRuntime`, `LocalizationCatalog` | Перевод ключей RU/EN. Новая система локализации не нужна. |
| `GameClock.Current` | Существующий `GameTimeSnapshot` передаётся команде как значение. Ядро не изменяет часы. |
| `GameSaveData`, `GameSaveController` | Фиксированный формат сохранения v1, без поля Messages и без владельца messaging runtime. Формат и контроллер не изменены. |

`PhoneMessages` — единственный владелец новой истории, контактов и read state. `PhoneConversation` и `PhoneMessage` дают публичное чтение, без публичных методов изменения. Отдельный класс Contact не нужен: контакт однозначно определяется стабильным `ContactId`; имя и avatar — метаданные presentation. Первый контакт приложения: **`landlord`**. Новые контакты не требуют нового C# типа.

Производственные файлы:

- `Assets/Game/Scripts/Phone/PhoneMessages.cs`: значения контента/направления, сообщения, переписки и команды владельца состояния.
- `Assets/Game/Scripts/Phone/PhoneMessagesSnapshot.cs`: сериализуемые DTO, отделённые от живого состояния.

Зависимости ядра: стандартная библиотека C# и существующий pure C# `GoLive.GameTime.GameTimeSnapshot`. Ни UnityEngine, ни UnityEditor не нужны.

## API

```csharp
var messages = new PhoneMessages();
messages.GetOrCreateConversation("landlord");

// ID задаёт вызывающая система. Повтор одной команды с тем же ID не дублирует сообщение.
messages.TryAddIncoming("landlord-rent-day1", "landlord",
    MessageContent.FromText("Мне нужны деньги..."), clock.Current);

// Доступно для будущих ответов; исходящее сообщение не обязано быть начальной историей.
messages.TryAddOutgoing("player-reply-001", "landlord",
    MessageContent.FromText("Заплачу завтра."), clock.Current);

// Будущий presentation binding вызывает это при фактическом открытии переписки.
messages.MarkConversationRead("landlord");

PhoneMessagesSnapshot snapshot = messages.CaptureSnapshot();
messages.Restore(snapshot);
```

Это пример использования API, а не автоматически выдаваемая игроку история. Первый контакт создаётся обычной командой. `TryAddIncoming` / `TryAddOutgoing` также создают переписку, если её ещё нет.

Для локализованного авторского сообщения используется `MessageContent.FromLocalizationKey(existingCatalogKey)`. Presentation позже разрешает его через текущую локализацию. `FromText` хранит буквальный текст, в том числе будущий ответ игрока; переключение языка не переводит пользовательский текст. Ключи и буквальный текст различаются явно. Домен не проверяет существование ключа в Unity-каталоге и не хранит готовые локализованные названия контактов.

## Правила состояния

- `MessageId` уникален во всём экземпляре `PhoneMessages`, включая разные контакты и направления. Повтор возвращает `false`, не перезаписывает текст, не создаёт контакт и не публикует изменение.
- ID сравниваются ordinal, с учётом регистра. Пустые ID/контент и неинициализированный `MessageContent` отклоняются через `ArgumentException`.
- История упорядочена по добавлению. Одинаковые или более ранние timestamps её не пересортировывают. Время каждого сообщения фиксируется из переданного `GameTimeSnapshot`.
- Входящее сообщение изначально непрочитано. Исходящее прочитано **игроком**, это не delivery/read receipt собеседника.
- `MarkConversationRead` помечает текущую историю указанного контакта; не затрагивает остальные контакты. Неизвестный контакт или уже прочитанная история дают `false`. Последующее входящее снова увеличивает unread.
- `UnreadCount` и `TotalUnreadCount` вычисляются из сообщений. Вторых сохраняемых счётчиков нет.
- Коллекции доступны только для чтения. После `Restore` нужно заново получить проекции контактов из владельца; сохранённые ссылки относятся к старому состоянию.
- `Changed` синхронно вызывается после commit; no-op команды молчат. `Restore` публикует одно общее изменение, без переигрывания incoming-команд.
- Контракт событий соответствует `PhoneSession`: исключение подписчика распространяется после commit и не откатывает сообщение. Подписчики отвечают за свои ошибки; нельзя считать такое исключение доказательством отсутствия сообщения. Тест покрывает этот случай и повторную команду из подписчика.
- Экземпляр принадлежит вызывающему игровому scope и используется на одном потоке. Он не зависит от активности меню. Thread safety, сетевой обмен и автоматический content seeding не входят в v1.

## Snapshot / дальнейшее подключение сохранений

Snapshot содержит собственную версию `1`, порядок контактов/сообщений, ContactId, MessageId, направление, тип и содержимое текста, игровые секунды и IsRead. Нет Unity-ссылок и runtime handles. Данные глубоко отделены от живого состояния в обе стороны. JSON round-trip проверен настоящим Unity `JsonUtility`.

`Restore` сначала строит и проверяет временные коллекции. Неподдерживаемая версия, null-записи/истории, пустые значения, дубликаты контактов/сообщений, неизвестные enum, отрицательное время и непрочитанное outgoing отклоняются **до изменения** текущей истории. Успешное восстановление заменяет состояние целиком, а не добавляет его повторно.

Для подключения к дисковому Save/Load позже потребуется:

1. Назначить экземпляру `PhoneMessages` владельца с lifetime игровой сессии и передавать его presentation явно. Не создавать его заново при каждом открытии View.
2. Добавить поле snapshot в `GameSaveData`; определить совместимость сохранений без этого поля и однократную выдачу начальной переписки. Сейчас старый save не изменяется.
3. Подключить capture/restore к существующему контроллеру. Для общей транзакции сначала проверить messaging snapshot на временном экземпляре вместе с остальными секциями; rollback всей игры остаётся ответственностью Save pipeline.
4. Подключить View к чтению проекций / `Changed`, а открытие конкретного чата — к `MarkConversationRead`. Предварительно выбранный ответ, compose box и отправка кнопкой не нужны.

Запись сообщений в текущий save-файл и замена mock UI **не выполнены и не заявляются** как готовая интеграция.
