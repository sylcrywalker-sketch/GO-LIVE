# Короткая проверка настоящего микрофона — 60–90 секунд

**Статус: сценарий подготовлен; новая проверка с голосом игрока ещё не проведена.** Прогон существующей записи через игру учитывается отдельно и не заменяет эту проверку.

## Подготовка

1. Откройте `GL` в Unity. Если модель речи ещё не установлена: **GO! LIVE → Voice → Install selected turbo speech model (548 MiB)**.
2. Запустите настроенную локальную модель чата через **GO! LIVE → Viewer Core → Start Local Model (LM Studio)**. Уже загруженная модель не должна загружаться повторно.
3. В тестовой игровой сессии откройте Streamly, подключите Trich и включите распознавание речи с языком **RU**. Начните эфир с 1–3 зрителями. Не удаляйте существующие сохранения ради проверки.
4. Откройте **GO! LIVE → Viewer Core → Reaction Monitor** и включите **Record session**. Для этой короткой проверки можно также включить **+ mic audio**: запись останется локально рядом с журналом в `Logs/ViewerSessions`.

## Что сказать

| Время после начала записи | Действие | Ожидаемый результат |
|---|---|---|
| 0–10 с | «Всем привет, парни. Как дела? Как настроение? Что сегодня делали?» | Смысл вопросов сохранён; определяется `PersonalQuestion`; обычно приходит один содержательный ответ о дне зрителя. |
| 10–25 с | Дождаться ответа. | Ответ содержит личный контекст зрителя, а не только приветствие. Нет придуманных покупок, железа, истории эфиров или денег стримера. |
| 25–35 с | «Так, секунду». Затем помолчать. | Обычно нет реакции на эту фразу. Отдельные фоновые реплики нужно отличать от ответа на неё. |
| 35–55 с | Обратиться к ответившему зрителю: «Жесть. Устал, наверное?» | Короткую беседу обычно продолжает активный собеседник; ответ соответствует предыдущей реплике и его состоянию. |
| 55–75 с | Дождаться продолжения и выключить **Record session**. | Журнал сохранён; беседа не превращается в неограниченный обмен репликами. |

Если ответ не пришёл, сохраните и этот журнал: не повторяйте удачные попытки вместо неудачной и не меняйте вероятности ради результата. Общие вероятности, присутствие зрителей, паузы и предел числа реплик проверяются также отдельными детерминированными тестами.

Распознавание может вернуть «Жесть. Устал, наверное.» или текст без пунктуации. Это всё ещё короткое обращение к активному собеседнику: отсутствие вопросительного знака само по себе не должно обрывать беседу. Если на первый вопрос ответили двое в пределах разрешённого второго ответа, активным собеседником считается зритель, чей разговорный ответ был опубликован последним к моменту этой фразы; это не обязательно первый ответивший.

## Отдельный повтор исходной записи: три фиксированные попытки

До просмотра результатов определены ровно три попытки с состояниями RNG аудитории **1, 2 и 3**, по одному запуску для каждого в этом порядке. Тест `SeventyFiveSecondRecordedConversationUsesTheProductionScenePipeline` читает `GO_LIVE_SHORT_ACCEPTANCE_SEED`: разрешены только `1`, `2`, `3`, по умолчанию `1`. Для каждой попытки задайте новый `GO_LIVE_SHORT_ACCEPTANCE_OUTPUT`; существующие каталоги результатов не перезаписываются. Сохраните все три результата, включая неудачные, без подбора seed или повторных запусков ради удачного ответа.

Все попытки используют один исходный корпус (`GO_LIVE_VOICE_CORPUS`, по умолчанию `Logs/VoiceCorpus/20260926-182411`): неизменённые участки `raw.wav` по отметкам **1/4/8** в `marks.json`, размещённые на **2/25/39-й секундах**, и **75 реальных секунд** в сцене `GL`. Меняется только начальное состояние уже существующего RNG аудитории `StreamSession`, через reflection внутри теста до начала эфира. Модель, вероятности, естественное присутствие зрителей, состояние дня и рабочий адаптер остаются обычными.

В `raw.jsonl` записываются заданное состояние `audience-rng-state` и фактический seed эфира `broadcast-seed`. Для каждой распознанной фразы сохраняются активный собеседник, его предыдущая реплика, возраст и число ходов беседы, присутствие и эпоха визита, речевые признаки и время. Проверка продолжения сравнивает ответившего с активным собеседником на момент третьей фразы, учитывая разрешённый второй ответ на первый вопрос. Эти повторы записи учитываются отдельно от новой проверки настоящего микрофона и не заменяют её.

## Что зафиксировать

Результаты выполненных трёх фиксированных повторов и их ограничения находятся в [отчёте коррекции](ViewerLowAudienceConversationReport.md): у обоих оставшихся собеседников продолжение опубликовано, первый собеседник ушёл; третий ответ требует проверки качества текста. Общий результат Explicit — один успешный тест и два неуспешных, включая ошибку шага скриншота после проверок диалога. Это не заменяет новую голосовую проверку.

Для каждой из трёх фраз нужны исходная расшифровка, речевой акт, задержка распознавания и задержка до видимой реплики. Для ответов — выбранный зритель, его состояние дня, план и разрешённые факты, ответ модели, решение проверки и показанный текст. В журнале Reaction Monitor уже сохраняются расшифровки, планы, выбранные зрители, задержки и решения; полный запрос/ответ модели дополнительно сохраняет автоматический прогон записанной речи.

Известное ограничение текущей записи: ник «Найт Оул» распознаётся неточно. Это не исправлялось заменой текста под конкретную фразу. Даже после успешной короткой проверки весь Viewer Core не считается завершённым.
