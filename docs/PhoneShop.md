# Магазин в телефоне — корзина и одна оплата

[+] на карточке и «В корзину» только кладут товар в корзину; деньги и заказы меняются только кнопкой «Заказать». Правила покупки живут в одном месте (`ShopCheckout`), корзина — отдельный объект без правил, экран магазина разделён на координатор и страницы, ничего из магазина не видно и не нажимается вне экрана Shop. Категории товаров — три широкие категории предметов (Еда / Электроника / Быт), общие с инвентарём.

## 1. Ответственность

| Класс | Отвечает за |
| --- | --- |
| `Wallet` (plain C#) | Единственный владелец денег. `TrySpend` либо отказывает без побочных эффектов, либо меняет баланс и только потом уведомляет — на этом построена фиксация оплаты. |
| `ShopCart` (plain C#) | Корзина сессии: `ProductId → количество` в порядке добавления, `Changed`. Цен, лимитов и денег не знает; не сохраняется. |
| `ShopOrderBook` (plain C#) | Оплаченные заказы: сохраняются, по ним работает доставка. Новые заказы добавляет только `ShopCheckout` (`internal TryReserveAll` / `CancelReservations` / `PublishChanged`). |
| `ShopCheckout` (plain C#) | Единственный владелец правил покупки и единственный способ заплатить: доступность, количество (≤ 99 на товар), лимит покупок с учётом прежних заказов, сумма (`checked`), баланс, создание заказов. `EvaluateQuantity` — то же правило для «в корзину» (без денег). |
| `ShopCatalogConfig` / `ShopProductDefinition` (ScriptableObject, только данные) | Товары: цена, лимит, доставка, категория (обязана совпадать с категорией доставляемого предмета — `Validate`), изображение: `DisplayImage` = своё, иначе иконка доставляемого предмета. |
| `ItemCategoryLocalization` (plain C#) | Одна таблица `ItemCategory → ключ` (`category.food` / `category.electronics` / `category.household`) для инвентаря и магазина. |
| `ShopBehaviour` (мост Unity) | Создаёт и держит корзину, книгу заказов и `ShopCheckout`; переводит строки корзины в строки оплаты по текущему каталогу; `Changed` при изменении баланса, заказов или корзины; сохранение/загрузка заказов. Своих правил покупки не содержит. |
| `ShopText` (plain C#) | Какими словами магазин называет состояние: бейдж карточки, подпись кнопки товара, причина, по которой нельзя оформить корзину, статус заказа, формат денег и счётчиков. |
| `PhoneShopView` (координатор) | Состояние презентации: открытая страница и выбранный товар. Запросы страниц → `ShopBehaviour`; данные отображения только для страницы на экране; заголовок (`TitleKey`, `PageChanged`) для `PhoneScreenView`. |
| `ShopStorefrontView` | Вкладки («Для тебя» + три категории; выбранная вкладка — состояние презентации), карточки, ярлыки «Корзина» и «Заказы» со счётчиками. |
| `ShopProductDetailsView`, `ShopCartView`, `ShopOrdersView` | Страницы товара, корзины и заказов. |
| `ShopProductCardView`, `ShopCartRowView`, `ShopOrderRowView` | Карточка и строки. |

Все представления получают свои элементы явными ссылками из сцены (`transform.Find` нет), ничего не решают и не хранят игрового состояния: рисуют готовые данные и поднимают запросы.

## 2. Правила

- [+] на карточке, «В корзину» на странице товара и «+» в строке корзины добавляют одну единицу в корзину. Деньги не списываются, заказ не создаётся. Отказ (нет в продаже; лимит, считая корзину и прежние заказы; 99 шт.) ничего не меняет: кнопка неактивна, бейдж или подпись говорит почему.
- Баланс проверяется только при оформлении: корзина может стоить больше, чем есть; тогда «Заказать» неактивна и видна причина «Недостаточно средств».
- «Заказать» — единственный путь к деньгам и заказам: вся корзина одной транзакцией, одно списание, по заказу на единицу (одна посылка на заказ), общее время оформления, срок доставки у каждого товара свой. После оплаты корзина пуста, открывается страница «Заказы».
- Фиксация: весь запрос проверяется до изменений → заказы резервируются без уведомления → одно списание (точка фиксации) → `Orders.Changed` один раз (в `finally`). Исключение подписчика `BalanceChanged` или `Orders.Changed` после списания не разводит кошелёк и заказы: заказы остаются, корзина очищается (`ShopBehaviour.TryCheckout` очищает её, как только книга заказов выросла). При отказе ничего не меняется и корзина остаётся.
- Во время одной оплаты вторая (из подписчика) получает `Busy`. Строки одного товара складываются только при одинаковых условиях; разные цены или лимиты для одного товара — `InvalidRequest`.
- Цена строки и итог на экране — `ShopCheckout.GetLineTotalCents` / `TryCalculateTotal`, те же формулы, что при оплате.

## 3. Экран магазина (сцена GL)

```
PhoneScreenCanvas
├─ Shop (PhoneShopView)                  телефон включает его только на экране Shop
│  ├─ Storefront (ShopStorefrontView)    CategoryTabs · Catalog/Content/ProductCardTemplate · Shortcuts (CartButton, OrdersButton)
│  ├─ ProductDetails (ShopProductDetailsView)  … AddToCart
│  ├─ Cart (ShopCartView)                List/Content/CartRowTemplate · Empty · Problem · Footer (Total, Checkout)
│  └─ Orders (ShopOrdersView)            List/Content/OrderRowTemplate · Empty
└─ BottomBar                             только общая кнопка «Назад»
```

- Навигация: витрина → товар / корзина / заказы. «Назад» на любой странице магазина возвращает на витрину, на витрине — на Home. Успешная оплата открывает «Заказы».
- Видимость: страница показана, только если телефон показывает экран Shop **и** она текущая. Все элементы магазина лежат внутри `Shop`; ярлык «Заказы» больше не стоит в общей нижней панели (раньше он был виден и нажимался на Home).
- Жизненный цикл: уход с экрана Shop или закрытие телефона выключает `Shop` → `OnDisable` отписывается и сбрасывает страницу на витрину (без `SetActive` во время деактивации), поэтому следующий визит начинается с витрины. Каждая команда ещё раз проверяет, что телефон в руке, открыт Shop и нужная страница, — клик по скрытой кнопке ничего не делает. Подписки симметричны в `OnEnable`/`OnDisable`; строки из пула отписываются в `OnDestroy`.
- Обновляется только страница на экране: по `ShopBehaviour.Changed`, смене языка, а страницы товара и заказов — ещё и по смене минуты (срок доставки).
- Карточка: изображение, название (одна строка, длинное — с многоточием), категория, цена (всегда видна, не обрезается), бейдж (нет в продаже > в корзине > заказан > куплен), кнопка [+] 36×36.
- Корзина: строка 122 px — изображение, название, категория, цена строки, «−», количество, «+», «x». Внизу над общей «Назад» — «Итого» и «Заказать», над ними строка причины; список заканчивается выше. Пустая корзина — «Корзина пуста», без итога и кнопки.
- Заказы: новые сверху; строка 108 px — название, оплаченная цена, статус, срок доставки (у доставленных скрыт).

## 4. Сохранение

Корзина не сохраняется: её нет в сохранении, загрузка её очищает. Схема сохранения не менялась (игра v6, `ShopOrdersSnapshot` v1). `RestoreOrders` сначала проверяет снимок целиком и только потом очищает корзину и заменяет заказы; отвергнутая загрузка не трогает ни заказы, ни корзину.

## 5. Что удалено

- Второй движок покупки: `ShopPurchase`, `ShopPurchaseResult`, `ShopBehaviour.TryPurchase` / `EvaluatePurchase`, `ShopOrderBook.TryReserve` / `TryCancelReservation`, `HasReachedPurchaseLimit`. Производственных вызовов `TryPurchase` не было, поэтому адаптер не оставлен; тесты покупают через корзину (`ShopTestData.Buy` / `BuyOne`).
- `categoryLocalizationKey` у товаров (28 строк каталога) и ключи `shop.category.*` (10), `inventory.food/electronics/household`, `shop.tab.food/electronics/household`, `phone.buy`.
- В сцене: старые шаблоны карточки и строки заказа, `BottomBar/OrdersButton`.

## 6. Тесты

- `ShopCartTests` (10), `ShopCheckoutTests` (23), `WalletTests` (3), `ShopCommerceTests` (3), `DeliveryStateTests` (23), `ShopTextTests` (19) — plain C#, без Unity: корзина, одна транзакция и её откат, лимиты с корзиной и заказами, переполнение суммы, исключения подписчиков после фиксации, повторный вход, тексты.
- `ShopBehaviourTests` (13, EditMode): «в корзину» не платит, деньги только при оформлении, корзина считается в лимит, оплата очищает корзину и при исключении подписчика, отказ её сохраняет, загрузка её очищает, у фасада нет пути к деньгам мимо `ShopCheckout`.
- `ShopCatalogDataTests` (25): категории товаров = категории доставляемых предметов и только три широкие, у каждой категории один ключ RU/EN, изображение с запасным вариантом, у каждого товара в продаже есть что показать, ключи интерфейса RU/EN.
- `ShopSaveIntegrationTests` (30): корзина не сохраняется, загрузка очищает корзину и сохраняет оплаченные заказы, отвергнутая загрузка корзину не трогает.
- `PhoneShopPlayModeTests` (10, сцена GL): цена, категория и изображение каждой карточки; [+] и «В корзину» только наполняют корзину; одна оплата за всю корзину и переход к заказам; без денег ничего не меняется; ничего из магазина не видно на Home и Messages и не попадает под лучи на Home; новый визит — с витрины (в том числе после закрытия телефона); строки корзины (1 и 8) и заказов (9, затем доставленные) читаются на русском и английском, «Заказать» не перекрывает «Назад».

## 7. Ручная приёмка (Game view 1920×1080)

1. Телефон → Shop: вкладки «Для тебя / Еда / Быт / Электроника», у каждой карточки цена и изображение.
2. [+] на двух товарах: баланс не меняется, на ярлыке «Корзина» счётчик 2, заказов нет.
3. Карточка → «В корзину»: то же; у товара с лимитом 1 кнопка становится «В корзине».
4. «Корзина»: строки, «−», «+», «x», итог; «Заказать» стоит над «Назад» и не перекрывает её.
5. Корзина дороже баланса: «Заказать» неактивна, «Недостаточно средств».
6. «Заказать»: одно списание, страница «Заказы», корзина пуста.
7. «Назад» до Home: ни ярлыков, ни страниц магазина; клик по их местам ничего не делает. Снова Shop — витрина.
8. То же на английском; день и ночь; консоль без ошибок и предупреждений.
